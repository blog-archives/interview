对。**标程 Agent 也只处理本轮分配的代码任务，完成后把结果或困难返回协调 Agent。** 是否采用、继续修改或请教师补充，由协调 Agent 决定。

它主要需要区分：已有代码、已有解法、需要尝试求解，以及条件还不够明确。

## 标程 Agent 流程

```mermaid
flowchart TD
    A([接收题目要求、解法说明<br/>已有代码及本轮任务]) --> B{当前提供了什么？}

    B -->|题目与明确解法| C[根据解法实现标程<br/>遵循语言和输入输出要求]

    B -->|明确题目，但没有解法| D[尝试推导可行解法并实现<br/>无法确定时保留疑点]

    B -->|已有标程或参考代码| E[根据任务检查、修改或适配代码<br/>保留无需改变的部分]

    B -->|计算规则仍不明确| F[列出影响实现的缺失条件<br/>或已有材料之间的冲突]

    C --> G[模型完成本轮代码工作<br/>静态检查逻辑、边界与复杂度<br/>整理尚未解决的问题]
    D --> G
    E --> G

    G --> H([返回协调 Agent<br/>候选标程、解法与复杂度说明<br/>以及检查结果和疑点])
    F --> H
```

### 这个 Agent 的几个约定

- **不必每次重新写代码。** 已有标程时，根据任务决定检查、局部适配或修改。
- **允许无法完成。** 难题可能只能返回部分思路、具体困难和所需补充信息，不强行交付一份标程。
- **代码是候选结果。** 当前只做静态分析，不执行代码，也不宣称保证通过。
- **不自行改变题目。** 如果只有修改数据范围或计算规则才能实现，应把建议返回协调 Agent。

和题面 Agent 相比，它更强调 **实现是否有依据、哪些问题尚未解决**。最终仍然是“完成本轮任务并返回”，不负责决定整个出题流程怎么继续。
