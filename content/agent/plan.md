这个助手可以采用 **预先确定的生成流程**：先明确目标，再分析历史表现、确定训练重点、选择题目，最后编排并检查计划。模型负责各节点中的分析与生成。

```mermaid
flowchart TD
    A([用户提出训练需求]) --> B[整理目标与约束<br/>训练方向、计划周期、每日可用时间<br/>当前水平与个人偏好]

    B --> C{关键信息是否足够？}
    C -->|否| D[追问缺失的目标或时间安排]
    D --> B
    C -->|是| E[查询相关学习记录<br/>近期做题、提交与已有评测结果<br/>提示使用情况、历史训练计划]

    E --> F[汇总学习表现<br/>知识点覆盖、通过率、错误类型分布<br/>重复提交与独立完成情况]

    F --> G[分析当前基础与薄弱环节<br/>结合用户目标确定需要补充的能力<br/>记录不足时采用保守的起点判断]

    G --> H[确定训练重点与先后顺序<br/>补前置知识 → 专项巩固 → 综合应用<br/>为各阶段分配时间预算]

    H --> I[检索题库中的候选题目<br/>匹配知识点、难度和先修要求<br/>区分新题与有意安排的复习题]

    I --> J[编排训练计划草稿<br/>按天或阶段安排题目、训练目的<br/>预计用时、完成要求与复习节点]

    J --> K[检查计划<br/>题目是否真实可用、难度是否衔接<br/>时间是否合理、是否覆盖用户目标]
    K --> L{检查结果}

    L -->|满足要求| M[生成训练计划书<br/>目标与学情依据、阶段安排、具体题单<br/>完成标准及必要的假设说明]

    L -->|可以内部调整| N[调整选题、题量或阶段安排<br/>保持用户目标与时间约束]
    N --> J

    L -->|目标与资源无法兼顾| O[说明缺题、时间不足等具体冲突<br/>请用户选择调整目标或约束]
    O --> B

    M --> P([交付计划书])
```

这里几个节点的职责需要分清：

| 节点 | 具体负责什么 |
|---|---|
| **汇总学习表现** | 由程序统计事实，例如某知识点做过几题、错误类型如何分布 |
| **分析薄弱环节** | 由模型结合事实判断训练重点；不能把“多次失败”直接等同于“不懂该知识点” |
| **确定训练顺序** | 先确定练什么、按什么顺序练，再去找题 |
| **检索与编排** | 从真实题库选题，并在时间预算内组织成可执行计划 |
| **检查计划** | 程序检查题目有效性、重复和时间合计；模型检查教学顺序与目标匹配 |

**历史记录不足也可以生成计划**，但应在前期安排少量摸底练习，并说明起点判断依据有限。当前流程先做到计划书交付，后续执行跟踪和动态调整可以另行设计。
