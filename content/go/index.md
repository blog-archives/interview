## 数据结构

- map 并发读写我什么是危险的

    Go 原生 map 没有内置锁，写操作可能触发渐进式扩容，修改桶链表与指针，并发读写会破坏底层内存结构；因此写时会设置 hashWriting 标记，若其他 goroutine 在此期间进行读或写就直接 panic，避免产生难以排查的内存错乱问题，并发场景可通过 Mutex 封装或 sync.Map 保证安全。

- map 扩容机制

    map 负载因子超过阈值，或是溢出桶数量过多就触发扩容，新建更大的桶数组，但不会一次性迁移全部数据，采用 **渐进式扩容**，每次增删查时顺带搬迁少量旧桶到新桶，全部迁移完成后释放旧桶内存，扩容期间访问会同时查新旧两组桶。

## GC

- 两次 STW 分别在做什么

    第一次 STW 停协程，开启写屏障，扫描根对象初始化灰色队列，之后放开协程做并发标记。第二次 STW 再次暂停，扫描所有协程栈补齐漏标记，处理剩余灰色对象，关闭写屏障，标记阶段结束，开始并发清扫。
