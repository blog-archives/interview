> 分类原则：每道题只保留一个主类型，按面试中占比最高的作答方式判定。Go、MySQL、Redis、MQ 等属于知识域，不再作为题型。

| 题型 | 英文标签 | 判断标准 |
|---|---|---|
| 原理问答题 | Concepts & Internals | 解释概念、机制、执行过程与适用边界 |
| 选型与权衡题 | Trade-off Analysis | 比较多个方案，结合约束给出选择与取舍 |
| 编码与算法题 | Coding & Algorithms | 需要算法、数据结构、伪代码或代码，并分析复杂度与边界 |
| 故障排查题 | Troubleshooting | 已出现异常，要求止损、建立证据链并定位根因 |
| 性能与容量题 | Performance & Capacity | 提速、降耗、消除长尾，或估算并发、吞吐与资源 |
| 专项设计题 | Focused Design | 设计边界明确的机制、流程或局部工程能力 |
| 系统设计题 | System Design | 从零设计完整系统、平台、框架或多组件子系统 |
| 工程实践题 | Engineering Practice | 围绕风险清单、预防、检测、响应与复盘形成工程闭环 |

### 按题型刷题的建议顺序

每个题型内部仍然先刷 P0，再刷 P1、P2。推荐按能力递进：

**原理问答 → 选型与权衡 → 编码与算法 → 故障排查 → 性能与容量 → 专项设计 → 系统设计 → 工程实践**

| 题型 | 建议答题框架 |
|---|---|
| 原理问答题 | 定义 → 核心机制 → 适用边界 → 优缺点 |
| 选型与权衡题 | 约束 → 比较维度 → 结论 → 代价与例外 |
| 编码与算法题 | 澄清约束 → 思路 → 实现 → 复杂度 → 边界用例 |
| 故障排查题 | 止损 → 观察 → 缩小范围 → 验证根因 → 修复与复盘 |
| 性能与容量题 | 基线 → 目标 → 建模或定位瓶颈 → 优化 → 压测验证 |
| 专项设计题 | 目标 → 约束 → 核心流程 → 异常与一致性 → 权衡 |
| 系统设计题 | 需求 → 容量估算 → 架构 → 数据模型 → 关键链路 → 高可用 |
| 工程实践题 | 风险 → 预防 → 检测 → 响应 → 演练与复盘 |
