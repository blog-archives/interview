## 开场白

面试官你好，我是苏桐渤，本科毕业于杭州师范大学软件工程专业。在校期间，我曾参与ACM实验室并获得了ICPC铜奖和CCPC银奖，这段经历极大提升了我的编程和问题解决能力。

毕业后，我一直在信友队做后端 web 开发，公司的核心业务主要是面向中小学生信奥竞赛的教学平台，包括题库系统、竞赛平台、线上授课等一些内容。作为协作者，我参与了绝大部分项目的开发，也能独立完成开发到交付的完整过程。不论是团队协作还是独立交付都具备较好的能力。此外，我也能积极参与团队的技术文档完善和流程优化，为提高团队的效率而努力。我认为自己需要跳出舒适圈，挑战更复杂的业务场景，拓宽技术视野，因此很荣幸能有机会面试贵公司。

## 离职原因

原公司业务和技术栈相对固定，日常以业务迭代和维护为主。希望能接触更多负责项目和场景，拓展技术视野。

## 第一阶段：基础认知与项目背景（入门层，确认项目真实性）
1. 简单介绍下题库系统，整体包含哪些核心模块，你的职责边界是什么，哪些部分是你独立完成？
2. 题库系统代码提交评测完整的业务流程是怎样的，从用户提交代码到返回结果，讲讲整条链路？
3. 竞赛系统主要解决什么业务场景，和题库系统在业务、流量特征上有哪些核心区别？
4. 信友队教学平台，阿里云MNS消息队列主要用来处理哪些异步任务，请描述下业务流程？
5. 三个项目都大量用到Gin+Gorm，在项目里Gorm你主要做了哪些配置、模型设计，遇到过哪些常见坑？

## 第二阶段：功能实现与技术选型（实践层，考察编码与组件使用）
### 题库系统相关
1. 项目里用到Redis做增量统计、定时落库，简单说下这个方案的实现思路，为什么不直接实时写数据库？
2. 定时落库是怎么做的？是Go内置定时器、crontab还是其他方案，如何保证定时任务多实例部署不会重复执行？
3. 夜间全量校正逻辑具体做什么，为什么需要校正，什么场景下会出现Redis统计数据和DB不一致？
4. 多维令牌桶限流，你是怎么设计多维度（短时、长时、单题）的令牌桶，限流的存储是放在Redis还是本地内存？各自优缺点？
5. 拦截恶意提交之后，业务上如何处理用户请求，直接返回错误吗，有没有做降级或者告警？

### 竞赛系统相关
1. 竞赛系统任务状态机，有哪些核心状态，状态流转是怎么设计的，用什么方式存储状态？
2. 什么是任务的幂等校验，评测任务在什么场景会重复分发，你的幂等是如何实现？
3. 赛后代码查重模块，讲讲你的实现逻辑，比对的是什么内容，做了哪些逻辑优化提升比对效率？
4. 分布式锁在竞赛系统中用在什么场景，用Redis实现分布式锁遇到过什么问题？

### 教学平台&MNS消息队列
1. 阿里云MNS消息队列，评测提交、自动交卷的消费逻辑是怎么写的，消息重复消费、消息丢失你如何处理？
2. MNS消息如果消费失败，你的重试、死信机制是怎么处理？

## 第三阶段：性能、高并发与问题排查（深度层，考察线上实战）
### 题库系统
1. 海量刷题提交场景，数据库压力主要来自哪里？除开Redis统计方案之外，还做过哪些数据库层面优化？
2. 高频恶意提交会挤占评测资源，限流之后，评测队列的压力下降效果如何，线上有没有遇到限流误杀正常用户，如何处理？
3. 如果Redis宕机，这套增量统计方案会出现什么问题，你做了哪些降级或者兜底？

### 竞赛系统（赛事瞬时高并发）
1. 赛事开赛瞬间流量暴涨，你做了Redis热点预热，预热的是什么数据，什么时候触发预热？
2. 接口拆分：通用数据与个人数据分开拉取，具体是怎么拆分，带来了哪些收益，前端是如何配合改造？
3. 任务异常巡检兜底机制，讲讲巡检逻辑，巡检发现异常任务之后怎么修复，会不会造成重复评测？
4. 赛事高并发场景，MySQL容易出现什么问题，你做过哪些索引优化、读写分离/缓存策略？
5. 如果评测服务大量堆积任务，队列阻塞，你会怎么排查定位问题，给出排查步骤？

### 通用业务问题
1. 多个项目大量使用Redis，讲下你项目中遇到过Redis的问题：缓存穿透、缓存击穿、缓存雪崩，项目中分别怎么规避？
2. Go协程在评测异步任务场景大量使用，你开发时如何控制协程数量，如何避免协程泄露，怎么捕获协程panic？

## 第四阶段：架构设计、权衡取舍（拔高层，考察方案思考）
1. 题库统计方案：Redis增量+定时落库+夜间校正，这套方案有什么缺点？如果让你重新设计，有没有其他可选方案，对比优劣？
2. 多维令牌桶限流，如果后续QPS继续上涨，本地限流和Redis分布式限流各自的取舍，什么场景适合用哪一种？
3. 竞赛系统任务状态机，如果业务继续扩张，任务量持续上涨，现有状态机架构会遇到什么瓶颈，可以怎么演进？
4. 消息队列MNS，如果切换到RabbitMQ/Kafka，你觉得现有业务需要做哪些改造，各自利弊？
5. 代码查重模块，当参赛人数上万，代码量很大，现有的比对逻辑会遇到什么瓶颈，如何优化？

## 第五阶段：复盘、风险与业务拓展（综合层，考察复盘与工程思维）
1. 回顾题库系统项目，上线之后遇到过哪些线上bug，怎么定位、修复的，后续做了什么规避？
2. 竞赛系统高并发治理，上线后做过哪些效果验证，有没有压测，压测指标是什么？
3. 如果现在要把题库、竞赛、教学平台做服务拆分，你会怎么拆分服务，拆分会带来哪些新问题？
4. 结合你简历提到的飞书机器人自动化工具，如果把这套自动化能力应用到题库、竞赛系统，你觉得可以解决哪些痛点？
5. 这几个项目中，你觉得自己做的最不满意的一个技术方案是什么，现在回头看会怎么优化？
