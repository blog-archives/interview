### 我更建议你的实际刷题顺序

虽然上面已经按 P0/P1/P2 排好了，但 **71 道 P0 也不建议机械地从第 2 题一路刷到第 129 题**。你前面已经在按“模块”构建知识体系，所以更适合在 **P0 内部继续分模块**。

例如第一阶段可以先攻：

**PaaS / 分布式基础**
> RPC → 分布式锁 → 分布式 ID → 微服务拆分 → RPC 超时 → 服务发现 → API Gateway → 配置中心 → 配置中心高可用 → 一致性 Hash → 灰度发布

然后是：

**MySQL → Redis → MQ → 分布式事务 → Go 性能排障 → 稳定性 → 安全。**

这样很多题实际上可以“一套知识回答五六道题”，131 道不会真的变成 131 套完全独立的答案。
