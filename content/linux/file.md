## Linux 常见目录

- 配置看 /etc
- 日志看 /var/log
- 用户文件看 /home
- 程序和库看 /usr
- 进程状态看 /proc
- 设备看 /dev
- 临时文件看 /tmp

| 目录 | 大致用途 | 后端开发常见场景 |
|---|---|---|
| `/` | 根目录，整个目录树的起点 | 它不是 root 用户的家目录 |
| `/etc` | 系统和服务的配置文件 | 查 Nginx、SSH、系统服务配置 |
| `/var` | 经常变化的数据 | 日志、缓存、数据库或服务运行数据 |
| `/var/log` | 系统和应用日志 | 服务故障时重点检查 |
| `/home` | 普通用户的家目录 | 用户代码、配置和个人文件 |
| `/root` | root 用户的家目录 | 与根目录 `/` 不是一回事 |
| `/tmp` | 临时文件 | 文件可能被系统清理，不能当作可靠存储 |
| `/usr` | 系统安装的程序、库和公共资源 | 常见程序位于 `/usr/bin`，库位于 `/usr/lib` |
| `/bin` | 基础命令 | 例如 `ls`、`cp`；现代系统中常链接到 `/usr/bin` |
| `/sbin` | 系统管理命令 | 现代系统中常链接到 `/usr/sbin` |
| `/dev` | 设备文件 | 磁盘、终端以及 `/dev/null` 等特殊设备 |
| `/proc` | 进程和内核运行信息的虚拟文件系统 | `/proc/进程PID`、CPU 和内存信息 |
| `/sys` | 内核设备和驱动信息的虚拟文件系统 | 查看或调整部分内核、设备状态 |
| `/run` | 系统启动以来的临时运行状态 | PID 文件、Socket 文件；重启后通常消失 |
| `/opt` | 可选的第三方软件 | 一些独立安装的软件会放在这里 |
| `/mnt`、`/media` | 文件系统或移动设备的挂载点 | 挂载数据盘、U 盘等 |


> `/` 和 `/root` 有什么区别？

`/` 是整个 Linux 文件系统的起点；`/root` 是 root 用户的家目录，作用类似普通用户的 `/home/用户名`。

> `/etc` 和 `/var` 的核心区别是什么？

`/etc` 主要保存系统和服务的配置；`/var` 保存运行过程中经常变化的数据，例如日志、缓存和部分服务数据。

> `/proc` 目录里的文件真的保存在磁盘上吗？

通常不是。`/proc` 是内核提供的虚拟文件系统，用文件形式展示进程和内核运行状态，关机后这些内容不会作为普通文件保存。

> `/tmp` 可以存放需要长期保留的数据吗？

不适合。`/tmp` 用于临时文件，系统重启或定期清理时可能删除其中内容，长期数据应该放到明确的持久化目录。

> `/bin` 和 `/usr/bin` 有什么区别？

传统上，`/bin` 存放系统启动和修复所需的基础命令，`/usr/bin` 存放其他常用程序。现代很多 Linux 发行版已经采用合并布局，`/bin` 实际上可能是指向 `/usr/bin` 的符号链接。

## RWX 权限

Linux 的 rwx 分别表示读、写、执行权限，每个文件会分别为所有者、所属组和其他用户设置一组权限。数字表示法中，r=4、w=2、x=1，把同一组权限相加即可。比如 755 表示所有者拥有 rwx，组用户和其他用户拥有 r-x；644 表示所有者可读写，其他人只能读。需要注意，rwx 对普通文件和目录的含义并不完全一样。

> 为什么不建议直接给文件或目录设置 `777`？

`777` 代表所有用户都可以读、写和执行，权限范围过大，容易造成文件被篡改或恶意程序被执行。生产环境应该遵循最小权限原则，只给实际需要的权限。

> `chmod` 和 `chown` 有什么区别？

`chmod` 修改文件的读、写、执行权限；`chown` 修改文件的所有者或所属组。一个解决“能做什么”，另一个解决“文件属于谁”。

> 为什么文件没有写权限，有时仍然可以被删除？

删除文件本质上是修改父目录中的目录项。因此，只要用户对父目录拥有 `w` 和 `x` 权限，通常就能删除文件，即使文件本身没有写权限。

> 目录只有 `r` 权限，没有 `x` 权限会怎样？

可以读取目录中的文件名列表，但通常无法进入目录，也无法正常访问其中具体文件的内容。对目录而言，`x` 表示进入和穿过目录的权限。

> `umask` 是什么？

`umask` 用来屏蔽新建文件或目录的默认权限。例如常见的 `022` 会去掉所属组和其他用户的写权限；新建文件通常得到 `644`，新建目录通常得到 `755`。实际结果还会受到创建程序指定权限的影响。

## 相关命令

| 命令 | 作用 | 常见用法 | 注意点 |
|---|---|---|---|
| `pwd` | 查看当前工作目录 | `pwd` | 执行复制、移动、删除前，可先确认当前位置 |
| `cd` | 切换当前目录 | `cd /var/log`：进入指定目录<br>`cd ..`：进入上一级<br>`cd ~`：回到家目录<br>`cd -`：回到上一次目录 | `cd` 是 Shell 内建命令；不带参数通常回到家目录 |
| `ls` | 查看目录内容 | `ls -l`：详细信息<br>`ls -a`：包含隐藏文件<br>`ls -h`：友好显示文件大小<br>`ls -lah`：常用组合 | `-h` 通常需要和 `-l` 配合；以 `.` 开头的是隐藏文件 |
| `cp` | 复制文件或目录 | `cp a.txt b.txt`：复制文件<br>`cp a.txt backup/`：复制到目录<br>`cp -r dir1 dir2`：复制目录<br>`cp -a dir1 dir2`：保留属性复制 | 目标存在时可能被覆盖；复制目录需要 `-r` 或 `-a` |
| `mv` | 移动文件或重命名 | `mv a.txt backup/`：移动<br>`mv old.txt new.txt`：重命名<br>`mv -i a.txt target/`：覆盖前询问 | 目标文件已经存在时可能被覆盖 |
| `rm` | 删除文件或目录 | `rm a.txt`：删除文件<br>`rm -r dir`：递归删除目录<br>`rm -i a.txt`：删除前询问<br>`rm -f a.txt`：强制删除 | 通常不经过回收站；使用 `rm -rf` 前必须确认目标路径 |
| `chmod` | 修改读、写、执行权限 | `chmod 755 app.sh`：设置数字权限<br>`chmod u+x app.sh`：给所有者增加执行权限<br>`chmod g-w file`：移除组写权限<br>`chmod -R 755 dir`：递归修改 | `-R` 会影响目录中的全部内容；不要随意使用 `777` |
| `chown` | 修改文件所有者或所属组 | `chown appuser file`：修改所有者<br>`chown appuser:appgroup file`：同时修改所有者和组<br>`chown -R appuser:appgroup dir`：递归修改 | 普通用户权限受限；递归修改前要确认目录范围 |

> 为什么 `cd` 必须是 Shell 的内建命令？

进程只能修改自己的工作目录。如果 `cd` 是独立进程，它只能改变子进程自己的目录，无法改变当前 Shell 的目录，因此必须由 Shell 自己执行。

> `cp` 和 `mv` 的核心区别是什么？

`cp` 创建一份新的文件副本，原文件仍然存在；`mv` 用于移动或重命名。相同文件系统内的移动通常只修改目录信息，跨文件系统移动则通常需要复制数据后再删除原文件。

> 执行 `rm` 后，文件内容会立即从磁盘消失吗？

不一定。`rm` 主要删除文件名与 inode 的关联；如果仍有进程打开该文件，数据和磁盘空间会继续保留，直到相关文件描述符被关闭。

> `ls -l` 输出的第一列应该怎么看？

第一个字符表示文件类型，例如 `-` 是普通文件、`d` 是目录、`l` 是符号链接；后面九位依次表示所有者、所属组和其他用户的 `rwx` 权限。

> 为什么不建议直接对整个目录执行 `chmod -R 755`？

因为它会给目录中的所有普通文件也添加执行权限，扩大权限范围。通常目录需要 `x` 才能进入，但普通配置文件和数据文件一般不需要执行权限，应根据文件类型分别设置。
