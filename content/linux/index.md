## 第一阶段必会清单



### 4. CPU 与内存排查

需要知道：

- CPU 使用率和 load average 的区别
- CPU 高时如何找到具体进程
- `free` 中 used、available、cache 怎么理解
- Swap 是什么
- 什么是 OOM，为什么进程会被系统杀死

需要会用：

`top`、`uptime`、`free`

第一阶段不需要深入内核调度算法，重点是能看懂现象。

### 5. 磁盘问题

需要知道：

- 磁盘容量不足和 inode 耗尽是两种问题
- `df` 和 `du` 分别看什么
- 为什么文件删除后，磁盘空间可能没有释放
- 日志文件为什么容易把磁盘写满

需要会用：

`df`、`du`、`lsof`

### 6. 网络和端口

需要知道：

- IP、端口、Socket 的基本关系
- 什么叫端口监听
- 如何确认服务监听在哪个地址和端口
- Connection refused 和连接超时的区别
- `127.0.0.1` 和 `0.0.0.0` 的区别
- `TIME_WAIT` 和 `CLOSE_WAIT` 大致意味着什么

需要会用：

`ss`、`curl`、`ping`、`dig` 或 `nslookup`

### 7. 服务管理

需要知道：

- 如何判断一个服务是否正在运行
- 服务启动失败时先看什么
- 为什么进程存在，不代表服务一定可用
- 重启服务和强制杀进程的风险

需要会用：

`systemctl`、`journalctl`

这两个主要适用于使用 systemd 的 Linux 环境；容器中不一定适用。

## 最应该练习的 5 道场景题

先把下面五道真正说顺，Linux 基础面试就有主干了：

1. 服务器上的接口突然变慢，你怎么排查？
2. CPU 使用率达到 100%，你怎么定位？
3. 内存不断增长甚至发生 OOM，你怎么排查？
4. 磁盘满了，你怎么定位和处理？
5. 服务访问不了，你如何从进程、端口、网络和日志逐层排查？

所以第一阶段不用追求“精通 Linux”，目标是：**看得懂权限，会查日志，会管理进程，能判断 CPU、内存、磁盘和网络问题。** 后面我们可以严格按照上面的顺序逐个学习。
