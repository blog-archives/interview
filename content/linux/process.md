## 程序、进程、线程的区别

程序是存放在磁盘上的静态代码和数据，本身不会运行；程序被加载执行后，就形成了进程。进程是操作系统进行资源管理和隔离的主要单位，拥有独立的虚拟地址空间、文件描述符等资源。线程是进程内部的执行单元，同一进程中的线程共享内存和大部分资源，但各自拥有栈、寄存器和执行位置。多进程隔离性更好但创建和通信成本通常更高；多线程共享数据方便，但需要处理竞态条件、锁和线程安全问题。

## PID 是什么

PID 是 Process ID，也就是操作系统为正在运行的进程分配的数字标。系统和用户可以通过 PID 查询进程状态、发送信号或管理进程。PID 只需要在当前 PID 命名空间和进程存活期间保持唯一，进程退出后这个数字可能被其他新进程复用。因此，PID 不是一个永久身份，也不能仅凭历史 PID 判断是不是原来的进程。

> PID 和 PPID 有什么区别？

PID 是当前进程的编号，PPID 是创建它的父进程编号。通过 PPID 可以还原部分进程父子关系，但父进程退出后，这种关系可能发生变化。

> PID 会一直保持不变吗？

进程？进程存活期间 PID 通常不变；进程退出后，PID 可以被系统复用。因此不能仅凭之前记录的 PID 判断当前进程还是不是原来的进程。

> Linux 中的 PID 1 有什么特殊之处？

PID 1 是系统或 PID 命名空间中的第一个进程。在传统系统中通常是 systemd 等初始化进程，负责启动服务、接收孤儿进程，并回收退出子进程留下的状态。

> 进程和线程的 ID 是什么关系？

Linux 中每个线程都有自己的线程 ID，也就是 TID；同一进程中的线程共享一个线程组 ID，用户通常把这个线程组 ID 看作进程 PID。主线程的 TID 通常与进程 PID 相同。

> 容器中看到的 PID 和宿主机上的 PID 为什么可能不同？

容器可以使用独立的 PID 命名空间。同一个进程在容器内部和宿主机上可能显示为不同的 PID，因此排查容器进程时要先确认自己所在的 PID 命名空间。

## 前台进程和后台进程

前台进程是当前终端正在直接交互和等待的任务，可以读取终端输入，终端通常会等待它执行结束后再接受下一条命令。后台进程不占用当前 Shell 的交互位置，Shell 可以继续执行其他命令，但它默认仍可能向终端输出内容。可以通过 & 启动后台任务，也可以使用 jobs、bg、fg 管理当前 Shell 的任务。需要注意，后台运行不等于守护进程，关闭终端后它仍可能因为收到 SIGHUP 等原因退出。

> 在命令后加 `&`，程序就能在关闭终端后继续运行吗？

不一定。`&` 只是让任务在后台运行，关闭终端后它仍可能收到 `SIGHUP` 而退出。可以使用 `nohup` 临时规避，但生产服务更适合交给 systemd 或容器平台管理。

> `Ctrl+C` 和 `Ctrl+Z` 有什么区别？

`Ctrl+C` 通常向前台进程组发送 `SIGINT`，请求程序终止；`Ctrl+Z` 通常发送 `SIGTSTP`，只是暂停程序，之后可以通过 `bg` 或 `fg` 继续运行。

> `jobs` 为什么看不到其他终端启动的后台进程？

`jobs` 查看的是当前 Shell 管理的作业，而不是系统中的全部进程。查看其他进程应该使用 `ps`、`pgrep` 或 `top`。

> 后台进程还能读取终端输入吗？

通常不能正常读取。如果后台进程尝试读取当前终端，Shell 的作业控制机制可能通过 `SIGTTIN` 将它暂停，切换到前台后才能继续交互。

> 后台进程和守护进程有什么区别？

后台进程只是暂时不占用当前终端；守护进程通常会与终端脱离，并由 systemd 等机制长期管理。后台进程不一定能在终端关闭后存活，也不一定具备自动重启和日志管理能力。

## SIGTERM 和 SIGKILL 的区别

SIGTERM 是请求进程正常终止的信号，进程可以捕获它并执行停止接收请求、完成在途任务、刷新数据和释放资源等清理逻辑。SIGKILL 是内核强制终止进程的信号，进程不能捕获、忽略或阻塞它，因此来不及执行应用层的清理逻辑。停止服务时应该先发送 SIGTERM，等待一段合理时间；只有进程无法正常退出时，才考虑使用 SIGKILL。强制终止可能造成请求中断、缓冲数据丢失或业务状态不一致。

> `kill` 命令默认发送的是哪个信号？

默认发送 `SIGTERM`，也就是请求进程正常退出。只有显式使用 `kill -9 PID` 或 `kill -KILL PID`，才会发送 `SIGKILL`。

> 后端服务收到 `SIGTERM` 后应该怎么实现优雅退出？

通常先停止接收新请求，再等待正在执行的请求完成，然后关闭数据库连接、刷新缓冲数据并释放资源。等待时间不能无限长，还需要设置超时并在超时后强制结束。

> 发送 `SIGTERM` 后进程为什么没有退出？

进程可能正在执行清理工作，也可能阻塞或忽略了 `SIGTERM`，还可能卡在某个系统调用中。应该先查看进程状态和日志，确认原因，而不是立即使用 `SIGKILL`。

> 使用 `SIGKILL` 有什么风险？

进程没有机会执行应用层清理逻辑，可能导致请求中断、缓冲数据未写入、临时文件残留或业务状态不一致。操作系统会回收内存和文件描述符，但无法替应用完成事务和业务补偿。

> 为什么执行 `kill -9` 后，进程有时仍然存在？

如果它是僵尸进程，实际上已经退出，只是在等待父进程回收状态，继续发送信号没有作用；如果处于不可中断睡眠状态，通常要等内核操作返回后才能完成退出。应根据进程状态处理父进程或底层 I/O 问题。

## 什么是优雅退出

优雅退出是指服务停止时，不直接强制杀死进程，而是先停止接收新任务，再处理完或安全中断正在执行的任务，最后释放资源后退出。常见触发方式是收到 SIGTERM，服务随后从负载均衡中摘除、关闭监听端口、等待在途请求完成，并关闭数据库连接和刷新必要数据。整个过程必须设置最大等待时间，避免某个请求卡住导致服务永远无法退出。超过超时时间后，管理系统才会考虑强制终止，因此业务仍需要通过超时、重试和幂等应对极端情况。

## 僵尸进程是什么，为什么产生

僵尸进程是已经执行结束，但退出状态还没有被父进程读取的子进程。子进程退出后，内核会释放它的大部分资源，但暂时保留 PID、退出码等少量信息，等待父进程通过 wait 或 waitpid 回收。如果父进程一直不回收，这条记录就会处于僵尸状态。少量僵尸进程通常不消耗 CPU 和大量内存，但大量积累会占用进程表和 PID，导致系统无法创建新进程。

## 相关命令

ps 用来查看某一时刻的进程快照，适合查询 PID、父进程、状态和资源占用；top 用来实时观察系统负载以及进程的 CPU、内存变化。pgrep 根据进程名称或命令行查找 PID，kill 则根据 PID 向进程发送信号，默认发送 SIGTERM。实际处理进程时，我会先用 pgrep 或 ps 确认目标，再发送正常终止信号，避免直接使用 kill -9。

| 命令 | 主要作用 | 常见用法 | 注意点 |
|---|---|---|---|
| `ps` | 查看进程的静态快照 | `ps -ef`：查看全部进程<br>`ps aux`：查看进程及资源占用<br>`ps -p 1234 -o pid,ppid,state,%cpu,%mem,cmd`：查看指定进程 | 命令执行完结果不会持续刷新；`STAT` 中 `R` 表示运行、`S` 表示睡眠、`Z` 表示僵尸等 |
| `top` | 实时查看系统和进程状态 | `top`：查看整机状态<br>`top -p 1234`：只观察指定进程<br>`top -H -p 1234`：查看指定进程中的线程 | 重点关注 load average、CPU、内存、进程状态；瞬时高峰不一定代表持续故障 |
| `pgrep` | 根据名称或命令行查找 PID | `pgrep nginx`：按进程名查找<br>`pgrep -a nginx`：同时显示命令行<br>`pgrep -f "java.*app"`：匹配完整命令行 | `-f` 匹配范围较大，可能找到无关进程；执行后续操作前要确认结果 |
| `kill` | 向指定 PID 发送信号 | `kill 1234`：发送 `SIGTERM`<br>`kill -TERM 1234`：请求正常退出<br>`kill -KILL 1234` 或 `kill -9 1234`：强制终止<br>`kill -0 1234`：检查进程是否存在及是否有权限发送信号 | `kill` 不等于强制杀进程；`SIGKILL` 应作为最后手段，僵尸进程也无法通过它清除 |
