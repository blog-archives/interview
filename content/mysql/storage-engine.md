## 执行一条 SQL 请求的过程

MySQL 处理一条 SQL 大致会经过 Server 层和存储引擎层：

1. **连接器**：建立连接、校验账号密码与权限。
2. **查询缓存**（MySQL 8.0 已移除）：命中则直接返回结果；未命中再继续往后走。
3. **解析器**：做词法分析和语法分析，生成语法树。
4. **预处理器**：做语义校验，例如表、字段是否存在，并处理别名等。
5. **优化器**：结合索引、统计信息等生成执行计划，例如是否走索引、表连接顺序等。
6. **执行器**：按执行计划调用存储引擎接口完成读写。
7. **存储引擎**：负责真正的数据存取，以及锁、事务、缓存等实现细节，最终把结果返回给客户端。

面试里如果问的是“一条 SQL 怎么执行”，通常默认连接已建立，重点讲 **解析 → 优化 → 执行**；如果问的是端到端完整链路，再补上连接器。

## 为什么 InnoDB 是默认引擎

因为 InnoDB 在功能、并发和可靠性上更符合现代业务需求。

1. **事务支持**：完整支持 ACID，适合对一致性要求高的业务。
2. **并发能力**：支持行级锁，读写冲突粒度更小，更适合高并发。
3. **崩溃恢复**：借助 redo log 等机制，在断电、进程异常退出后也能恢复到一致状态。

相比之下，早期常用的 MyISAM 不支持事务和行锁，在数据安全和并发上短板明显。MySQL 从 5.5 起将 InnoDB 设为默认引擎，正是为了更好满足企业级场景对事务、并发和可靠性的要求。

## InnoDB 和 MyISAM 的不同

| 对比项 | InnoDB | MyISAM |
|---|---|---|
| 事务 | 支持 | 不支持 |
| 索引结构 | 聚簇索引：完整数据行存放在主键索引叶子节点。若未显式定义主键，会选用唯一非空索引，或生成隐藏主键。辅助索引叶子节点存主键，通常需要回表，因此主键不宜过大。 | 非聚簇索引：数据和索引分离，索引叶子节点存的是数据文件指针；主键索引与辅助索引相对独立。 |
| 锁粒度 | 最小到行锁，并发更好 | 最小到表锁，更新时容易锁整表，并发受限 |
| `COUNT(*)` | 不缓存精确总行数，无过滤条件时通常要扫描；带 `WHERE` 更要按条件统计 | 会维护表的总行数，无过滤条件的 `COUNT(*)` 可直接返回 |
| 外键 | 支持 | 不支持 |
| 崩溃恢复 | 支持 | 较弱 |

## 数据文件大体分成哪几种

常见相关文件可以按用途这样理解：

- `db.opt`：库级元数据，如默认字符集、排序规则（MySQL 8.0 起这类信息更多收敛到数据字典，不再依赖该文件）。
- `*.frm`：表结构定义文件（MySQL 8.0 起表元数据进入数据字典，例如 `mysql.ibd`，不再使用 `.frm`）。
- `*.ibd`：InnoDB 独立表空间文件，存放对应表的数据和索引。开启 `innodb_file_per_table`（默认开启）时，每张表通常对应一个 `.ibd`；共享表空间场景下，数据会落到 `ibdata1` 等系统表空间文件。
- MyISAM 还会看到 `*.MYD`（数据）和 `*.MYI`（索引）。

补充：undo log、change buffer 等并不一定落在业务表自己的 `.ibd` 里，更多位于 undo 表空间或系统表空间，具体取决于版本和配置。
