## Redis 的分布式锁具体是怎么实现的？

核心用 `SET key value NX PX ttl`：不存在才写入，并带过期时间，保证加锁原子性。

要点：

1. **value 用唯一标识**（UUID / 请求 ID），解锁时用 Lua 校验「是自己的锁」再 `DEL`，避免误删别人的锁
2. **必须设 TTL**，防止进程崩溃导致死锁
3. 业务未完成锁过期 → 可续期（Redisson Watch Dog）或把 TTL 设够长
4. 单机 Redis 够用大多数场景；要更高可靠可用 RedLock，但争议大，生产更常见是 Redis + 主从/哨兵，接受极端情况下锁失效

口述：`SET NX PX` 加锁 → Lua 校验 value 后删除解锁 → 必要时自动续期。

## 排行榜该用哪种数据结构？

用 **ZSet（有序集合）**。

- `ZADD` 写入 member + score（如积分、分数）
- `ZREVRANGE` / `ZRANGE` 按排名取 Top N
- `ZRANK` / `ZREVRANK` 查某人名次
- `ZINCRBY` 给分数做增减

score 天然有序，适合排行榜。

## 字符串类型有没有指令能对已存数字累加？

有：`INCR` / `INCRBY`（整数），`INCRBYFLOAT`（浮点）。

对应还有 `DECR` / `DECRBY`。key 不存在时会当 0 再加；值不是合法数字会报错。

## 缓存雪崩、穿透、击穿分别是什么？怎么解决？

| 问题 | 是什么 | 怎么解 |
| --- | --- | --- |
| **雪崩** | 大量 key 同时过期，或 Redis 挂了，请求打爆 DB | 过期时间加随机值；多级缓存；Redis 高可用；限流降级 |
| **穿透** | 查根本不存在的数据，缓存和 DB 都没有，每次打到 DB | 缓存空值（短 TTL）；布隆过滤器拦截非法 key |
| **击穿** | 热点 key 突然过期，高并发同时打 DB | 热点永不过期 / 逻辑过期；互斥锁（只让一个线程回源重建） |

区分口诀：雪崩是「一片一起挂」，穿透是「从来没有」，击穿是「一个热点刚好过期」。
