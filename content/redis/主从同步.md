
Redis 主从复制，**全部同步请求都是从节点主动发起**，基于 PSYNC2 协议，分为**全量同步**和**部分重同步（增量）**。

1. **首次建立同步：全量同步** 从节点向主节点发送 PSYNC 命令请求同步。 主节点收到后，如果没有可用的 RDB 快照，会 fork 子进程执行 BGSAVE 生成 RDB；如果已有正在生成 / 现成 RDB，则直接复用。 与此同时，主节点维护一块环形固定大小的**复制积压缓冲区**，记录 RDB 生成期间新产生的所有写命令。 RDB 生成完成，主节点把 RDB 文件传输给从节点。 从节点收到 RDB，先清空本地原有数据，加载 RDB 快照。 快照加载完毕，主节点再把复制积压缓冲区中这段积压的写命令发给从节点，从节点重放命令，追平主节点数据，全量同步完成。
2. **正常运行阶段：持续增量复制** 同步完成后，**从节点每秒向主节点发送 REPLCONF ACK，上报自己当前复制偏移量，充当心跳**。 主节点收到 ACK 之后，将新产生写命令持续写入复制积压缓冲区，同时转发给从节点执行重放，持续保持主从数据一致。
3. **网络抖动断开后的重连：部分重同步** 网络发生短暂断开，从节点重新连上主节点，再次发送 `PSYNC replid offset`，携带主节点 ID 与自己上次的复制偏移量。 主节点做两个判断：

- replid 匹配，确认还是原来的主节点；
- offset 仍然存在复制积压缓冲区范围内。

条件全部满足：直接把缓冲区 offset 之后的命令发送给从节点，**部分重同步，不需要全量**。 如果 replid 不匹配，或者 offset 已经超出复制积压缓冲区：退化为完整全量同步流程。

> 补充：复制积压缓冲区是环形有限大小，如果断网时间太久，旧偏移量被环形缓冲区覆盖，就只能全量同步。

1. Q：什么是部分重同步，解决什么问题？ A：PSYNC2的部分重同步，网络短暂断开重连后，利用replid+复制偏移量，直接补发缓冲区后续命令，避免每次断连都做全量RDB同步，降低开销。
2. Q：部分重同步依赖哪几个核心要素？ A：①replid主节点ID；②复制偏移量offset；③复制积压缓冲区repl‑backlog‑buffer。
3. Q：复制积压缓冲区是什么？ A：主节点上一块**固定大小环形缓冲区**，记录最近执行的写命令，用于部分重同步，新数据会覆盖最老数据。
4. Q：什么情况下部分重同步会失败，退化成全量同步？ A：①replid不匹配（主节点发生切换）；②从节点的offset已经被环形缓冲区覆盖，找不到对应数据。
5. Q：全量同步的时候主节点一定执行BGSAVE吗？ A：不一定。如果已有正在生成的RDB快照会直接复用，没有现成RDB才fork子进程执行BGSAVE。
6. Q：全量同步阶段，从节点本地原有数据会怎么样？ A：从节点加载RDB前，会清空自身所有原有数据。
7. Q：REPLCONF ACK作用是什么？ A：①从节点上报自身复制偏移量；②充当心跳，让主节点感知从节点存活；③供min‑replicas‑to‑write判断从节点延迟。
8. Q：主从复制，是主主动推送数据给从吗？ A：不是。从节点每秒发REPLCONF ACK上报offset，主收到后才转发写命令；同步请求全部由从节点发起。
9. Q：复制积压缓冲区调大还是调小好？ A：网络容易抖动、断连时间长，调大，减少全量同步概率；但会占用更多主节点内存。
10. Q：主从复制过程，主节点会阻塞吗？ A：BGSAVE fork子进程不阻塞主进程；但是传输RDB会消耗带宽；大量写命令堆积会压满复制积压缓冲区。
11. Q：Redis2.8、4.0关于PSYNC有什么差别？ A：2.8是PSYNC1，只支持一个replid，主节点切换后无法部分重同步；4.0推出PSYNC2，支持两个replid，主切换后依然有机会部分重同步。
12. Q：min‑replicas‑to‑write的作用？ A：配置最少健康从节点数量，达不到该数量，主节点拒绝执行写命令，防止主单点故障造成数据丢失。
13. Q：主从复制存在哪些缺陷？ A：主节点写无法自动故障转移；异步复制存在数据丢失风险；主节点写压力大时，从节点会产生复制延迟。
14. Q：主从复制数据是同步还是异步？ A：默认异步复制，主执行完写命令直接返回客户端，不等待从节点完成复制。
15. Q：什么是复制偏移量？ A：主、从各自维护的数字，代表已经处理完成的复制流字节数；从节点通过REPLCONF ACK上报给主节点。
16. Q：主节点怎么感知从节点挂掉？ A：依靠REPLCONF ACK心跳，超过超时时间没有收到从节点的ACK，则判定从节点断开。
17. Q：从节点怎么感知主节点挂掉？ A：检测TCP连接断开，收不到主节点复制流数据；原生主从没有自动选主能力，需要哨兵。
18. Q：主节点宕机重启，replid会变化吗？会带来什么影响？ A：重启后replid会变更；旧从节点重连，replid不匹配，直接触发全量同步。
19. Q：复制积压缓冲区是每个从节点一份吗？ A：不是，**一个主节点全局只有一份复制积压缓冲区**，所有从节点共用。
20. Q：主从复制会占用从节点大量内存吗？ A：数据全量同步加载RDB会占用；复制缓冲区只存在主节点，不从节点分配。
